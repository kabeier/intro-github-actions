  2. Make these four files (the lesson's, word for word) and a .gitignore:

    index.js

    function factorial(num) {
  let product = 1;

  for (let i = num; i > 0; i--) {
    product = product * i;
  }

  return product;
}

module.exports = factorial;

3 · run-tests.yml on a dev branch

Create .github/workflows/run-tests.yml (the lesson's):

name: Run Test Suite

on:
  push:
    branches:
      - dev

  pull_request:
    branches:
      - main

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 18

      - name: Install dependencies
        run: npm install

      - name: Install Jest
        run: npm install jest

      - name: Run tests
        run: |
          npm test || (echo "❌ Tests failed" && exit 1)
git checkout -b dev
git add .
git commit -m "Run tests in CI"
git push -u origin dev

4 · Break a test, read the red ✗

In main.test.js, change expect(factorial(3)).toBe(6); to toBe(7), then:

git add .
git commit -m "Break a test"
git push
FAIL ./main.test.js
  ✕ tests factorial(3) = 6

  ● tests factorial for small numbers › tests factorial(3) = 6

    Expected: 7
    Received: 6

Tests:       1 failed, 6 passed, 7 total
❌ Tests failed
Error: Process completed with exit code 1.

Change it back to toBe(6), commit, push: green again.

5 · A pull request into main

  1. On github.com: Compare & pull request (base: main ← compare: dev) → Create pull request.
  2. At the bottom of the PR, the Run Test Suite check runs (event: pull_request). Wait for ✓, then Merge pull request.
  3. The merge is a push to main: Run Test Suite does not run for it (its push trigger is dev only).

Want a red check to actually block merging? Settings → Branches → add a rule for main → require status checks to pass.

6 · Run it by hand: workflow_dispatch

Add workflow_dispatch: under on: (lined up with push:). Once that's on main, the workflow's page gets a Run workflow button. Every finished run also has Re-run all jobs.

Without the trigger, a manual start is refused: Workflow does not have 'workflow_dispatch' trigger.

7 · The Docker version

Replace run-tests.yml with the lesson's Docker version. The runner already has Docker; your Dockerfile installs Node and Jest:

name: Run Test Suite

on:
  push:
    branches:
      - dev

  pull_request:
    branches:
      - main

  workflow_dispatch:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Build Docker image
        run: docker build -t app-test .

      - name: Run tests in container
        run: docker run app-test
git checkout dev
git add .
git commit -m "Run the tests in Docker"
git push
✓ Checkout repository
✓ Build Docker image
✓ Run tests in container
    > trial@1.0.0 test
    > jest
    PASS ./main.test.js
    Tests:       7 passed, 7 total

Check: you're done when…

  1. Your repo has a red ✗ run (the broken test) followed by a green ✓ run
  2. Your pull request shows a passing Run Test Suite check, and it's merged
  3. The Docker version is green
