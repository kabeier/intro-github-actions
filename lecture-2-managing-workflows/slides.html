Mental model: GitHub Actions is your local workflow, repeated in a clean environment.

run-tests.yml, on a dev branch

name: Run Test Suite

on:
  push:
    branches:
      - dev

  pull_request:
    branches:
      - main

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 18
      - name: Install dependencies
        run: npm install

      - name: Install Jest
        run: npm install jest

      - name: Run tests
        run: |
          npm test || (echo "❌ Tests failed" && exit 1)
git checkout -b dev
git add .
git commit -m "Run tests in CI"
git push -u origin dev

Run it again without a new commit

on:
  push:
    branches:
      - dev
  pull_request:
    branches:
      - main
  workflow_dispatch:
  • workflow_dispatch = "can be started by hand". The workflow's page gets a Run workflow button
  • Any finished run also has Re-run all jobs (top right)
  • Use them to re-check a flaky failure or debug the workflow, without junk commits

Without it, GitHub refuses: "Workflow does not have 'workflow_dispatch' trigger".

  • The Run workflow button appears once the workflow with workflow_dispatch is on the default branch (main). Merge first, then show it.
  • Tested: before adding the trigger, starting it by hand failed with that exact message (HTTP 422).

Workflows are code

  • Edit them in your editor, commit them, keep their history
  • Change them on a feature branch, open a pull request, get a review
  • Don't assume a workflow works: watch its first run

A broken workflow can let broken code through. Review it like code.

"History lets you see how the pipeline evolved, and revert it if a change breaks CI."

diagrams/GA2-03-native-vs-docker.tldr

The curriculum's table: native = small projects, build time matters, fast feedback, Docker not needed. Docker = environment parity critical, native dependencies, production in containers, "works here == works everywhere".

The Docker version

name: Run Test Suite

on:
  push:
    branches:
      - dev
  pull_request:
    branches:
      - main
  workflow_dispatch:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
      - name: Build Docker image
        run: docker build -t app-test .
      - name: Run tests in container
        run: docker run app-test
✓ Checkout repository
✓ Build Docker image
✓ Run tests in container
    docker run app-test
    > trial@1.0.0 test
    > jest
    PASS ./main.test.js
    …
    Tests:       7 passed, 7 total
